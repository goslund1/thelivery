# AAR — 2026-10-09: Mobile & Touch work order, Phases 0–6

One long session. Jason dropped a work order in `Drop Offs/` ("The Livery — Mobile & Touch Work Order") to make thelivery a working tool on a phone. The headline job is entering a tune from the Xbox screen, and the desktop layout must not move. All seven phases (0–6) were built, the close-out docs were written, and everything is live. Along the way it found and fixed three existing bugs and two bugs of my own, one of them destructive. What's left is Jason's device shakedown.

## What was done

## Bugs found that predated this work (fixed)

- **Discard and Exit didn't revert tuning edits** (Phase 4). `RecipeSection`'s reset copied the recipe into `local`, which fired the sync `local.upgrades` watcher. Its `flush()` read the tuning panel's stale rows and wrote the discarded values back. Fixed with `suppressFlush` around the reset.
- **"Undo Order" never appeared** on the first photo-manager open of a visit (Phase 5). The snapshot watcher was keyed on `isManage`, which stays true between opens.
- **Phantom unsaved card on every page load** (`9f06f55`). Same cause as the Discard bug, in `onMounted`'s variant apply. It armed "Leave site?" for every visitor.

## Bugs I introduced (fixed)

- **A touch step could press "Reset Stock"** (live from Phase 3 until `9f06f55`). The steppers act on `pointerdown`. A step can open the Springs prompt under the finger, and in Chromium the tap's click then landed on Reset Stock, zeroing alignment, springs and damping. `@touchstart.prevent` turned out not to be enough. The fix is a 400ms tap-through guard on both prompts. Jason was asked to check the History of any tune edited with the steppers on a touch device in that window.
- **A ghost click stole the value box's focus** and closed prompts (Phase 3). Fixed with `@touchstart.prevent`, which handles focus but not the case above.
- **Edit Card's hit area anchored to the card** after E3 made the button `position: static`. Its `::after` covered the tuning panel. Fixed with `relative`.
- **Subtitle row ran up to 68px past the card edge** once its controls grew (Phase 2). Fixed with `width: 0` plus `flex: 1` on the selects.

## What went wrong

- **The harness lied for a phase.** Playwright's beyond-viewport element screenshot silently drops touch emulation, so the tall touch shots and every audit after them ran as a mouse device. It was caught in Phase 2, when the first run said none of the fixes applied. The harness now grows the viewport for tall shots and asserts touch before audits.
- **My test saves damaged Jason's local data.** A save test zeroed 11 of Smokin's tune values in `backend/data.db` (the tap-through bug above). My first restore used the wrong history version: `card_history` snapshots the state *before* a save, so the true pre-test state was v24, not v23. Meanwhile my repeated saves had pushed v24 past the 20-version prune. A scratchpad copy saved it, and Smokin is now verified identical to v24 field by field. Jason's July versions in local History are gone. Lesson saved to memory: snapshot the card JSON before any save test.
- **Debugging by guessing.** E4's restore bug took three wrong fixes before I traced the actual write with a store subscription and stack (`$subscribe` with `flush: 'sync'` plus `Error.stackTraceLimit`). Tracing first would have saved the detours, and the same technique found the phantom and the Reset Stock write in one run each.
- **One mistaken claim, caught by measurement.** I said nothing would jump at the 1067px boundary; it moved 10px until the left gutter was made to grow.

## Decisions Jason made

- Grow dense edit controls to 44px on touch.
- The value-box keyboard flow applies everywhere (desktop behaviour change).
- Undo button on touch only; steppers for visitors too.
- Photo manager in two columns on phones.
- Commit the baseline PNGs, then later untrack them (audits stay tracked).
